## 1. 반드시 지켜야 하는 작업 순서 ★

이 순서를 어기면 사고가 납니다. **매번 이 순서대로 하세요.**

```
① 시작 전 : 최신 내용 받기   (git pull / GitHub Desktop 의 Fetch origin)
② 작업     : Claude 에게 시키기
③ 확인     : npm run dev 로 눈으로 보기
④ 검사     : npm run build 가 성공하는지
⑤ 올리기   : commit + push       ← ★ 이걸 안 하면 아무 일도 일어나지 않습니다
⑥ 확인     : Vercel 이 🟢 Ready 인지
```

### ①이 필요한 이유

다른 사람이(또는 내가 브라우저에서) 이미 파일을 고쳤을 수 있습니다.
받지 않고 작업하면 **서로 다른 내용이 충돌**합니다.

- GitHub Desktop: 왼쪽 위 `Fetch origin` → `Pull origin` 클릭
- 터미널: `git pull`

### ⑤가 가장 흔한 실수입니다 ★

**내 컴퓨터에서 파일을 고쳐도, 올리지 않으면 실제 사이트는 절대 바뀌지 않습니다.**

브라우저에서 고칠 때는 `Commit changes` 를 누르는 순간 올라갑니다.
하지만 내 컴퓨터에서는 **'고치기'와 '올리기'가 별개**입니다.

"고쳤는데 사이트가 안 바뀐다"의 90%가 이것입니다.

**Claude 에게 시키는 것이 가장 편합니다.** 이렇게 말하세요.

```
방금 고친 내용을 커밋하고 푸시해 줘.
```

**✅ 확인하는 방법:** GitHub Desktop 에서 `Push origin` 버튼이 사라지고
바뀔 것이 없다고 나오면 올라간 것입니다.

### 어느 가지(branch)에서 작업하나

**`main` 에서 그대로 작업하세요.** 내려받으면 기본으로 `main` 입니다.

`main` 에 올리면 → Vercel 이 자동으로 실제 사이트를 새로 만듭니다.
브라우저에서 고치는 것과 완전히 같은 길입니다.

> 다른 이름의 가지(`new-template`, `feat/...`)가 보이지만 **신경 쓰지 마세요.**
> 사이트를 만드는 동안 쓴 작업용 가지이고, 지금은 `main` 과 내용이 같습니다.

> ★ 이것이 브라우저 방식보다 나은 가장 큰 점입니다.
> 브라우저에서는 올린 뒤에야 실패를 알 수 있지만, 여기서는 올리기 전에

**★ 설치한 그대로의 Claude Code 는 화면을 볼 수 없습니다. ★**

Claude 는 파일을 읽고 고치고, `npm run dev` 같은 명령을 실행할 수는 있지만,
**브라우저를 열어 눈으로 확인하지는 못합니다.** 그래서 기본 흐름은 이렇습니다.

```
Claude 가 고친다  →  내가 브라우저에서 본다  →  본 것을 Claude 에게 말한다
```

이렇게 말하면 됩니다. **내가 본 것을 구체적으로 알려 주는 것**이 요령입니다.

```
휴대폰에서 참가 신청 화면을 보니 폼 안쪽에 스크롤바가 하나 더 생겨.
narrowPhone 값을 2200 에서 2400 으로 올려 줘.
```

```
종목 안내 화면에서 BottleSumo 카드만 다른 카드보다 세로로 길어 보여.

> ⚠️ **"화면을 열어서 확인해 줘" 라고 시키지 마세요.**
> 할 수 없는 일이라 거절하거나, 최악의 경우 **화면을 보기 위한 프로그램을
> 새로 설치하겠다고 제안**할 수 있습니다. 비개발자가 승인하기에는 너무 큰
> 변경입니다. 그런 제안이 나오면 **아니라고 하세요.**

### 2-4-1. (선택) Claude 가 화면을 직접 보게 하려면 — Claude in Chrome

크롬 확장 프로그램 **Claude in Chrome** 을 깔면, Claude 가 브라우저를 열어
화면을 보고 스크린샷을 찍을 수 있게 됩니다. **꼭 필요한 것은 아닙니다.**
다만 폼 높이 재기(3-4번)에는 확실히 편합니다.

#### 필요한 것

| | |
| --- | --- |
| 브라우저 | 크롬, 엣지, 또는 Brave·Arc·Vivaldi·Opera |
| 확장 프로그램 | **Claude in Chrome** (크롬 웹스토어), 버전 1.0.36 이상 |
| 요금제 | **Pro · Max · Team · Enterprise 중 하나** |
| 로그인 방식 | `claude` 실행 후 브라우저 로그인 (`/login`) |

> ⚠️ **API 키로 로그인한 경우에는 동작하지 않습니다.** 브라우저 로그인이어야
> 합니다. 위 0-3번 ②대로 로그인했다면 문제없습니다.
>
> ⚠️ **WSL(윈도우 안의 리눅스)에서는 지원되지 않습니다.** 윈도우에서
> 0-3번 권장 방법으로 설치했다면 해당 없습니다.

#### 설치 순서

1. 크롬에서 웹스토어의 **Claude in Chrome** 페이지를 엽니다.
   `https://chromewebstore.google.com/detail/claude/fcoeoabgfenejglbffodgkkbkcdhcgfn`
2. **`Chrome에 추가`** 를 클릭해 설치합니다.
3. **크롬을 완전히 닫고 다시 엽니다.** (이 단계를 빠뜨리면 연결되지 않습니다)
4. 프로젝트 폴더에서 터미널을 열고, 아래처럼 `--chrome` 을 붙여 실행합니다.
   ```
   claude --chrome
   ```
5. 처음 한 번은 설명 창이 뜹니다. `Enter` 를 누릅니다.
6. Claude 가 브라우저를 처음 쓰려 할 때 허락을 묻습니다. **허락하세요.**

> 📷 [스크린샷: 크롬 웹스토어의 Claude in Chrome 페이지 —
> `docs/images/11-claude-in-chrome.png` 로 넣고 이 줄을
> `![Claude in Chrome 설치](images/11-claude-in-chrome.png)` 로 바꾸세요]

#### 잘 연결됐는지 확인하기

Claude 안에서 **`/chrome`** 을 입력하세요.
**`Status: Enabled`** 와 **`Extension: Installed`** 가 보이면 성공입니다.

- 매번 `--chrome` 을 붙이기 번거로우면, `/chrome` 에서 **`Enabled by default`** 를 고르세요.
- 연결이 끊기면 `/chrome` → **`Reconnect extension`**.
- `Not detected` 로 나오면 **크롬을 다시 시작**하고, 그다음 Claude 도 다시 시작하세요.

## 7. 문제가 생겼을 때

### 7-1. `npm install` 이 실패한다 (프로젝트 폴더에서)

1. **올바른 폴더에 있는지** 확인합니다. `dir`(맥은 `ls`)에 `package.json` 이 보여야 합니다. 안 보이면 0-2번 방법으로 터미널을 다시 여세요.
2. **Node.js 버전**을 확인합니다. `node -v` → `v20.9.0` 이상이어야 합니다.
3. 회사 컴퓨터의 **보안 프로그램이나 방화벽**이 막을 수 있습니다. 전산 담당자에게 문의하세요.
4. 그래도 안 되면 **브라우저 방식(`RUNBOOK.md`)으로 하세요.** 그것만으로도 대부분의 운영이 가능합니다.

### 7-1-1. Claude Code 설치에서 권한 오류가 난다 (`npm install -g`)

`npm install -g` 로 설치하려 할 때 아래 같은 오류가 흔합니다.

```
npm error code EPERM        (또는 EACCES)
npm error Error: EPERM: operation not permitted
```

```
npm warn EBADENGINE Unsupported engine
npm warn EBADENGINE   required: { node: '>=22.0.0' }
```

**해결 방법은 다시 설치하지 않는 것입니다 — 0-3번의 권장 방법을 쓰세요.**

```
irm https://claude.ai/install.ps1 | iex
```

이 방법은 **관리자 권한도, Node.js 도 필요하지 않습니다.** 위 두 오류가
모두 생기지 않습니다. 이미 `npm install -g` 로 시도해 실패했더라도,
그냥 이 명령을 실행하면 됩니다.

> `EBADENGINE` 은 오류가 아니라 **경고**입니다. Node 가 22 미만일 때 나오며,
> 설치가 되기도 합니다. 다만 정상 동작을 보장하지 않으니 권장 방법을 쓰세요.

**✅ 확인하는 방법:** `claude --version` 이 버전과 `(Claude Code)` 를 함께
출력하면 성공.

### 7-2. `npm run dev` 가 열리지 않는다

- 이미 3000번을 다른 프로그램이 쓰고 있으면 자동으로 다른 번호로 열립니다.
  **터미널에 나오는 주소를 그대로** 읽어서 그 주소로 여세요.
- Claude 에게 이렇게 말해도 됩니다.
  ```
  개발 서버가 안 열려. 터미널 메시지를 보고 원인을 찾아 줘.
  ```

### 7-3. 올릴 때 충돌이 났다

"conflict" 라는 말이 나오면, 내가 고친 곳을 다른 사람도 고친 것입니다.
**혼자 해결하려 하지 말고 Claude 에게 맡기세요.**

```
푸시하려는데 충돌이 났어. 상황을 확인하고 해결해 줘.
어떤 내용이 사라질 수 있는지 먼저 알려 줘.
```

### 7-4. Claude 가 엉뚱한 것을 고쳤다

**아직 올리지 않았다면** 아무 문제 없습니다.

```
방금 한 작업을 전부 되돌려 줘.
```

**이미 올렸다면** 되돌린 뒤 다시 올리면 됩니다.

```
마지막 커밋을 되돌리고 푸시해 줘.
```

> ⚠️ 잘못 올려도 **방문자에게 고장난 화면이 보이지는 않습니다.** 파일 모양이
> 깨지면 새 사이트 만들기가 실패하고, 실패하면 **이전 사이트가 그대로
> 서비스됩니다.** 겁먹지 마세요. (`RUNBOOK.md` 1-3 참고)

### 7-5. 고쳤는데 실제 사이트가 안 바뀐다

순서대로 확인하세요.

1. **올렸나요?** (1번의 ⑤) — 가장 흔한 원인입니다.
